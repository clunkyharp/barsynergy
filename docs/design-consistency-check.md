# Design Consistency Check

Дата: 2026-04-29

## Статус

Этот документ больше не должен использоваться как самостоятельный итоговый verdict по дизайн-системе.

Причина:

- в промежуточной версии он описывал stabilization-pass слишком оптимистично;
- после финального mixed audit выяснилось, что реальная зрелость системы ниже;
- часть выводов про `PASS` и `3 stabilized` уже не отражает текущую точку честно.

## Что из старого документа остается полезным

- мысль, что runtime/tokens/docs должны обновляться в одном батче;
- проверка shared fields / alerts / tables / panels как базовой дисциплины;
- требование не плодить локальные примитивы без причины.

## Что из старого документа больше нельзя считать актуальным

- формулировку `pass with active stabilization follow-up` как общий статус;
- неявное предположение, что система уже близка к полной стабилизации;
- представление, что проблемой остался только table/mobile/accessibility follow-up.
