# Security

## Phase 0 Rules

- Passwords are stored only as hashes.
- Sessions are stored in PostgreSQL.
- Main user session is not JWT.
- Cookies must be `httpOnly`; production cookies must be `secure`.
- Login and public business-access registration must be protected by persistent rate limits.
- Admin pages must be protected by role checks before real data is added.
- Do not log passwords or full personal data.
- Do not send full personal data to Telegram.
- Do not automatically send vacancy responses or resume files to employers before admin review and explicit candidate consent.
- Validate env with Zod.
- Validate future form input with Zod on the server.
- Validate uploads by mime type, extension, size, file signature, auth and permissions.

## Current Security Controls

- Login and business-access registration use `AuthAttemptThrottle` for persistent per-email and per-IP throttling.
- Login performs a dummy bcrypt comparison for unknown emails to reduce timing-based email enumeration.
- Public application forms use a separate `ApplicationSubmissionThrottle`.
- Public content image uploads require matching MIME type, filename extension and image signature.
- Private resume uploads require matching MIME type, filename extension and document signature.
- Local `/uploads/...` serving is allowed only for local storage, path-contained files and public `UploadedFile` records.
- Production Nginx sets baseline security headers, including HSTS, clickjacking protection, `nosniff`, referrer policy and permissions policy.
- Nginx overwrites `X-Forwarded-For` with `$remote_addr` before forwarding to the app, so app-level throttles do not trust spoofed inbound forwarding chains from direct clients.
- The app generates CSP in Next proxy with a per-request nonce. Production `script-src` uses the nonce without `unsafe-inline` or `unsafe-eval`; development keeps only `unsafe-eval` for local tooling.
- Current dependency remediation pins `next` to the fixed exact release and overrides the transitive `fast-xml-builder` advisory path through npm `overrides`. Project `.npmrc` enables exact saves and audit by default.
- Admin draft deletion actions enforce `ContentStatus.DRAFT` inside the server-side delete filter before image cleanup can run.
- Business-access invites can be activated only while the application is `APPROVED`, the user is `PENDING`, the business account is `PENDING`, the invite is unused and the token has not expired. Stale or racing activation attempts fail inside one transaction.
- When a business-access application moves away from `APPROVED`, unused activation invites for that application are invalidated.
- The demo screen seed script is local-only: it requires `BARSYNERGY_ALLOW_DEMO_SEED=true`, a non-production environment, local PostgreSQL `DATABASE_URL` and `DEMO_BUSINESS_PASSWORD`.

## Security Remediation 2026-05-17

The 2026-05-17 security batch remediates six finding groups:

- Dependency advisories: `next` is pinned to `16.2.6`; npm override forces transitive `fast-xml-builder` to `1.2.0`.
- Admin draft deletes: article, event, course, vacancy, supplier, partner and general-sponsor draft deletes include `ContentStatus.DRAFT` in the server delete filter.
- Business-access invites: activation requires approved application plus pending user/account state, and transaction count checks reject stale or racing activation.
- Business-access lifecycle: unused invites are deleted when an approved business-access application is moved to a non-approved status.
- Demo seed: demo screen data seeding requires explicit local-only environment controls and no hardcoded demo business password.
- Headers and CSP: CSP is generated by Next proxy with a request nonce; production Nginx provides HSTS and no static script CSP.

## Production Data

User personal data must be stored on Russia-compatible infrastructure.

Google Forms is allowed only for anonymous surveys and research forms without personal data.
It is not allowed for applications, contacts, files, registration, vacancy responses, partners, suppliers or any personal-data collection.
