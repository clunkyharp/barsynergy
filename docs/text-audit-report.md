## Раздел 1. Критические проблемы

### Проблема 1. Непоследовательные названия разделов в навигации

**Страница:** Header, Footer, страницы About, Partners
**Описание:** Один и тот же раздел называется по-разному в разных частях сайта. Пользователь не может уверенно связать пункт меню со страницей.

| Место | Текст |
|-------|-------|
| Header nav | «Партнёрам» |
| Footer nav | «Для партнёров» |
| Page eyebrow | «Для партнёров» |
| Header nav | «Образование» |
| Page title | «Обучение для бариста и команд» |
| Footer link | «О нас» |
| Page title | «О проекте» |

**Почему критично:** Навигационная путаница. Пользователь нажимает «Образование», попадает на страницу «Обучение» и не уверен, что попал куда хотел.

**Рекомендация:**
- Навигация: **«Обучение»** (не «Образование»), и заголовок страницы тоже «Обучение».
- Навигация и страница: **«Партнёры»** везде (header, footer, eyebrow, breadcrumb).
- Footer и страница: **«О проекте»** (не «О нас»).

**Файлы для правки:**
- `src/components/layout/site-header.tsx:13` — navItems label
- `src/components/layout/site-footer.tsx:38` — footer link text
- `src/app/(public)/education/page.tsx:19` — metadata title

### Проблема 2. «Для бизнеса» не соответствует содержимому

**Страница:** `/business`
**Цитата:** «Разместите ваш кофейный бар в каталоге СКФО»
**Проблема:** Название раздела «Для бизнеса» создаёт ожидание услуг/инструментов для бизнеса. На деле это форма добавления в каталог поставщиков. Пользователь-владелец заведения кликает «Для бизнеса» и ожидает CRM, аналитику или сервисы, а видит анкету для каталога.

**Почему критично:** Несоответствие ожиданий = отказ. Владелец заведения уходит, не поняв, что ему тут делать.

**Рекомендация:**
- Переименовать раздел в **«Каталог заведений»** или **«Добавить заведение»** в навигации.
- Либо добавить подзаголовок-уточнение в hero: «Раздел для добавления кофейного бара или specialty-проекта в каталог BARSYNERGY».
- Убрать текст «Это не страница консалтинга и не заявка на разработку» — определение от противного говорит о проблеме именования, а не помогает пользователю.

**Файлы для правки:**
- `src/components/layout/site-header.tsx:19` — nav label
- `src/app/(public)/business/page.tsx:80-83` — hero title, description, summary

### Проблема 3. Термин «бармен» вместо «бариста» в FAQ

**Страница:** Главная (FAQ)
**Цитата:** «Платформа рассчитана на барменов, управляющих, владельцев заведений...»

**Почему критично:** Целевая аудитория — specialty-профессионалы. «Бармен» и «бариста» — разные профессии в их восприятии. Неточность подрывает экспертность.

**Рекомендация:** Заменить «барменов» на «бариста».

### Проблема 7. Дублирование секций на главной

**Страница:** `/`
**Описание:** На главной есть три секции, которые ведут к одним и тем же страницам:
1. **«Разделы»** — карточки (Обучение, Афиша, Вакансии, Материалы, Калькулятор, Поставщики)
2. **«Роли»** — карточки (бариста → /education, владелец → /business, поставщик → /suppliers, бренд → /partners)
3. **«Актуальное»** — карточки (вакансии, материалы, поставщики)

Плюс отдельные секции «Ближайшие события» и «Читать», которые тоже ведут на /events и /articles.

**Проблема:** Пользователь видит 5 разных способов попасть на одни и те же 6 страниц. Это путает, а не помогает.

**Рекомендация:**
- Объединить «Разделы» и «Роли» в одну секцию: сверху показать роль, ниже — релевантные разделы.
- Убрать «Актуальное» как отдельную секцию или заменить на ленту свежих карточек без дублирования.
- Порядок: Hero → Роли → Разделы → Событие → Материал → Спонсоры → FAQ.

**Файл:** `src/components/public/homepage-client.tsx:765-851` — порядок секций в HomepageClient

### Проблема 8. Отсутствие команды/людей на странице «О проекте»

**Страница:** `/about`
**Описание:** Страница рассказывает что такое BARSYNERGY, но не показывает кто за ним стоит. Нет имён, фото, ролей.
**Откуда приходит пользователь:** Хочет узнать, кому доверять.
**Главный вопрос:** Кто эти люди и можно ли им доверять?
**Отвечает ли страница:** Нет.

**Рекомендация:** Добавить блок «Команда» с именами и ролями (хотя бы 2-3 человека). Даже минимальная персонализация повышает доверие.

**Действие:** Задача для контент-менеджера (не правка кода).

### Проблема 9. Непоследовательная терминология для «заведение»

**Страницы:** Весь сайт
**Описание:** Одно и то же понятие называется по-разному:
- «кофейный бар» (20+ вхождений)
- «кофейня» (5+ вхождений)
- «заведение» (15+ вхождений)
- «точка» (1 вхождение, education)
- «бар» (как сокращение)
- «specialty-проект» (business page)

**Проблема:** Пользователь не уверен, что его формат подходит. Если платформа «для кофейных баров», подходит ли обычная кофейня?

**Рекомендация:** Зафиксировать в редполитике:
- **Основной термин:** «заведение» (универсальный) или «кофейный бар» (если это действительно фокус).
- **Допустимые уточнения:** «кофейня», «бар», «обжарочная» — только когда нужно конкретизировать.
- **Избегать:** «точка», «specialty-проект» без пояснения.

**Действие:** Системное — нужна редполитика (см. Раздел 6).

## Раздел 4. Сильные места сайта

### Сильное место 1. Тексты кнопок

**Страницы:** Весь сайт
**Почему работает:** Почти все CTA начинаются с глагола и сообщают, что произойдёт: «Найти обучение», «Связаться с командой», «Описать задачу», «Рассчитать себестоимость», «Заполнить заявку».
**Рекомендация:** Использовать как образец. Исключить оставшиеся generic кнопки («Подробнее», «Повторить»).

### Сильное место 2. Страница консалтинга

**Страница:** `/consulting`
**Почему работает:** Конкретные направления с описанием результата, цены с нижней границей (от 15 000 ₽), кейсы с задачей и результатом. Пользователь получает достаточно информации для решения.
**Рекомендация:** Страница-эталон для остального сайта по уровню конкретики.

### Сильное место 3. Cookie notice

**Компонент:** `cookie-notice.tsx`
**Почему работает:** Короткий, понятный текст. «Используем только необходимые: для входа и форм. Никакой рекламной аналитики.» — честно, конкретно, без юридического тумана.

### Сильное место 4. Контактная форма с динамическими подсказками

**Компонент:** `contact-application-form.tsx`
**Почему работает:** При выборе темы обращения меняются поля формы и подсказки. Пользователь видит только релевантные поля. Label сообщения адаптируется: «Описание вакансии» для вакансий, «Что поставляете» для поставщиков.

### Сильное место 5. Валидация форм

**Компонент:** `public-form-validation.tsx`
**Почему работает:** Человеческие сообщения об ошибках: «Email нужно заполнить», «Укажите email в формате name@example.com», «Подтвердите согласие, чтобы отправить форму». Не технические коды, а понятные инструкции.

### Сильное место 6. Страница 404

**Файл:** `not-found.tsx`
**Почему работает:** Чёткий заголовок, подсказка «Проверьте адрес», три карточки с разделами для быстрого перехода. Пользователь не теряется.

## Раздел 6. Рекомендации по процессу

### 6.1. Нужна редполитика

**Что зафиксировать:**
- Основной термин для заведения: «кофейный бар» или «заведение».
- Список допустимых синонимов и контексты их применения.
- Форма обращения: «вы» (строчная).
- Тон: деловой, конкретный, без маркетинговых штампов. Образец — страница консалтинга.
- Правило: каждый CTA начинается с глагола.
- Правило: максимум 25 слов в предложении.

### 6.2. Нужен глоссарий терминов

Для страниц, ориентированных на новых пользователей, нужно пояснять:
- **specialty** — категория кофе и заведений, работающих со specialty-зерном
- **каппинг** — дегустация кофе по профессиональному протоколу
- **экстракция** — процесс заваривания кофе, извлечение вкуса из зерна

Глоссарий может быть отдельной страницей или tooltip'ами при первом вхождении.

### 6.3. Шаблон для новых страниц

Каждая новая публичная страница должна содержать:
1. **Eyebrow** — название раздела (совпадает с навигацией).
2. **H1** — конкретный заголовок, отвечающий на вопрос «что я здесь найду».
3. **Description** — одно предложение с конкретикой (что, для кого, регион).
4. **Primary CTA** — действие, начинающееся с глагола.
5. **Summary** — подсказка что делать дальше.

### 6.4. Чек-лист перед публикацией контента

- [ ] Заголовок понятен без контекста?
- [ ] Нет стоп-слов: «профессиональный», «комплексный», «индивидуальный подход»?
- [ ] Кнопки начинаются с глагола?
- [ ] Предложения короче 25 слов?
- [ ] Термины пояснены или очевидны для аудитории?
- [ ] Названия разделов совпадают с навигацией?
