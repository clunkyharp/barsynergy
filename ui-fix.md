2. Core UX Issues
2.1. Неочевидная точка входа для основной аудитории
Что не так: Hero-секция предлагает два действия: «Найти обучение» и «Смотреть афишу». Но платформа обслуживает минимум 3 роли: бариста (ищет обучение/работу), владелец кофейни (ищет персонал/поставщиков), бренд/поставщик (ищет каналы). Hero обращается только к первой роли.

Влияние: Владелец кофейни, пришедший за поставщиком или за кандидатом, не видит своего сценария на первом экране.

Решение: Заменить статичные CTA на адаптивный блок «Кто вы?» или добавить 2–3 роле-специфичных входных точки под hero (как на сайтах Notion/Linear: «For teams» / «For individuals»).

2.2. Навигация: 11 пунктов без группировки
Что не так: Мобильное меню содержит: События, Обучение, Вакансии, Поставщики, Материалы, Для бизнеса, Партнёры, Спонсорство, Консалтинг, О проекте, Контакты. Это одноуровневый flat-list.

Влияние: Пользователь не может быстро найти нужный раздел — все 11 пунктов визуально равнозначны. «Для бизнеса», «Партнёры», «Спонсорство» и «Консалтинг» — по сути одна группа (B2B-предложения), но поданы как отдельные сущности.

Решение:

Группировка: Платформа (События, Обучение, Вакансии, Поставщики, Материалы) + Сотрудничество (Для бизнеса, Партнёры, Спонсорство, Консалтинг) + О нас (О проекте, Контакты)
На desktop: мегаменю с группами. На mobile: аккордеон-группы
2.3. Два логина без объяснения
Что не так: Существует /auth/login («Вход в кабинет», для бизнес-пользователей) и /admin/login («Вход для команды»). В мобильном меню внизу есть только «Войти», которое ведёт на один из них.

Влияние: Пользователь может не понять, какой логин ему нужен. Ошибка ?error=invalid показывается при первом посещении /auth/login?error=invalid — это конфуз: пользователь ещё ничего не ввёл, а уже видит ошибку.

Решение:

Убрать показ ошибки при первичном визите (только после реальной попытки)
На странице /auth/login добавить явный заголовок для кого это: «Для заведений и специалистов» vs «Для команды BARSYNERGY»
2.4. Пустые состояния на листингах без контента
Что не так: На странице «Афиша» (events) при отсутствии событий показывается заголовок «Готовим новые события» с описанием типов событий — это хорошо. Но EmptyState компонент использует одинаковый паттерн Card с border-left accent для всех случаев, не различая «нет данных» и «нет результатов поиска».

Влияние: Пользователь, который ввёл поисковый запрос и не получил результатов, видит тот же шаблон, что и пользователь на пустой странице. Нет подсказки «попробуйте другой запрос».

Решение: Разделить empty states на 2 типа: «раздел пуст» (с описанием, что будет) и «нет результатов» (с кнопкой «сбросить фильтры»).

3. Core UI Issues
3.1. Контраст секций на белом фоне
Что не так: Body background — #ffffff. Секция карточек (home-section-card) имеет bg: rgba(255, 255, 255, 0.94), border #e0e2e8 (1px). Между hero и карточками — переходная зона, которая при определённых размерах экрана выглядит как огромная белая пустота.

Влияние: При скролле пользователь теряет ощущение контента — страница «проваливается» в белое ничто.

Решение:

Добавить фоновый тон для секции карточек: var(--background-band) = #f7f8fa
Усилить border карточек до #c7cad5 (--border-strong) или добавить subtle shadow
Уменьшить gap между hero и секцией карточек
3.2. Типографика hero: размер заголовка
Что не так: Hero-заголовок «Обучение, вакансии и поставщики для кофейных баров Северного Кавказа» занимает 4 строки на mobile. Заголовок перечислительный и длинный.

Влияние: На мобильном экране заголовок съедает ~60% viewport — CTA-кнопки и подзаголовок уходят далеко вниз.

Решение: Сократить заголовок до 2 строк: «Платформа для кофейных баров СКФО» или «Всё для кофейного бара в одном месте». Детали перенести в подзаголовок.

3.3. Однообразные page headers
Что не так: Все листинговые страницы (Вакансии, Поставщики, Материалы, Афиша) имеют идентичный паттерн: breadcrumb → title → description → yellow CTA button → фильтры → список. Фоновый градиент (бежевый) одинаковый.

Влияние: Пользователь не чувствует перехода между разделами — все страницы «на одно лицо». Нет визуальных маркеров принадлежности к разделу.

Решение:

Добавить цветовые акценты по разделам (events = coral, education = blue, suppliers = green) через иконку или тонкую полоску
Или использовать уникальные фоновые иллюстрации/паттерны для каждого раздела в header
3.4. Кнопки: слишком много primary-кнопок на экране
Что не так: На странице partners видны две yellow primary CTA рядом: «Описать партнёрскую задачу» и «Смотреть спонсорство». На главной: «Найти обучение» (yellow) + «Смотреть афишу» (text-link). На about: «Связаться с командой» (yellow) + «Найти обучение» (outline).

Влияние: Когда два primary-action рядом, пользователь не понимает, что важнее.

Решение: Один primary CTA на секцию/блок. Второй — всегда secondary (outline/ghost).

3.5. Блок фильтров визуально тяжёлый
Что не так: На страницах listings (vacancies, suppliers, events) блок «Фильтры» занимает значительную часть viewport: поисковая строка + «Показать параметры» (свёрнутый аккордеон). Между header и первым результатом — 2 крупных визуальных блока, создающих «стену» перед контентом.

Влияние: Пользователь должен прокрутить ~400px прежде чем увидит первый результат. При 2-3 результатах в базе (текущее состояние) это несоразмерно.

Решение:

Компактифицировать: поиск + inline-чипы фильтров в одну строку
Или перенести фильтры в sidebar на desktop
Или скрывать блок фильтров по умолчанию, если результатов < 10

5. Design System / Consistency Review
5.1. Что хорошо
Токены: 70+ CSS custom properties — комплексная и продуманная система
Компонентная библиотека: 40+ UI-компонентов в src/components/ui/ — EmptyState, ErrorState, Button, Card, FormField, Toast, Dialog и т.д.
Accent color #e8b000 (gold) используется консистентно через var(--accent)
Типографика: display-шрифт (serif) для заголовков + sans-serif для body — хороший контраст
Радиусы: 4 ступени (--radius-sm через --radius-xl) — последовательно
Семантические цвета: success/warning/danger + field states — проработаны
5.2. Что проблемно
Inconsistency #1: Два стиля CTA-ссылок

На одних страницах: «Читать материал ↗» (arrow-up-right)
На других: «Откликнуться →» (стрелка вправо)
На третьих: «Перейти →»
Три разных паттерна для одного действия «перейти по ссылке».
Inconsistency #2: Стиль карточек

Homepage section cards: белые с border + icon + title + description + arrow
Event cards: белые с category tag + title + description + text-link
Article cards: с image cover + badges + title + description + text-link
Vacancy cards: с meta tags + title + salary
Четыре совершенно разных паттерна карточек. Некоторая разница оправдана типом контента, но базовая структура (spacing, border treatment, hover state) должна быть единой.
Inconsistency #3: «ПОКАЗАТЬ ПАРАМЕТРЫ»
Uppercase button-style для аккордеона фильтров — не соответствует остальным expand/collapse элементам на сайте (например, «Свернуть» в education — lowercase link style).

Inconsistency #4: Admin login vs User login
Два дизайна форм авторизации с разным лейаутом, разным размером полей, разным размещением элементов. Они должны быть визуально единообразны.
